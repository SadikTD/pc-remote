# v2 Own Streaming Engine and Remote Access: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Every task is TDD (listed tests first, watch them fail, implement, watch them pass, then commit). In line with the user's direction to save tokens for real work, tasks give exact files, interfaces, tests and done-criteria rather than full code.

**Goal:** Replace Sunshine and Moonlight with our own capture → encode → PRS/UDP → decode engine, auto-connect on the LAN, and reach the PC from anywhere (hole punching, with Cloudflare TURN as fallback).

**Architecture:** see the spec. Two independent tracks share only `docs/stream-protocol.md`, the PRS additions to `docs/protocol.md`, and `docs/prs-vectors.json`:
- **Track H** (Windows host, Rust, `host/`);
- **Track P** (Android, Kotlin, `app/`).

Phase 3 (remote) and Phase 4 (cleanup) follow, once both tracks have landed.

**Spec:** `docs/superpowers/specs/2026-10-16-pc-remote-v2-own-engine-design.md`. **Protocol:** `docs/stream-protocol.md`.

## Global Constraints
- Byte layouts, crypto, FEC and timings come only from `docs/stream-protocol.md`. Shared vectors live in `docs/prs-vectors.json`: Track H generates them, and Track P's tests read them from `../docs/prs-vectors.json`.
- Host: no new runtime processes or services. Idle (no stream) means no capture, encoder or timers: under 5 MB private RAM, ~0% CPU. Streaming at 1080p60: under 3% CPU (GPU encode).
- Phone: no Google Play services dependency. APK stays under 8 MB until Phase 4, then a ~3 MB target.
- Every user-visible string goes in `strings.xml` (phone) or `host/ui`. The Midnight design tokens apply everywhere.
- Build commands:
  - phone: from `P:` (`subst P: "D:\All Tools Source Code\PC Remote"`) with `JAVA_HOME="/c/Program Files/Microsoft/jdk-21.0.12.101-hotspot"`;
  - host: `PATH="$HOME/.cargo/bin:$PATH"`.
- Real-device checks run on the user's phone: `adb -s 24efc44a` (Xiaomi 24117RK2CC, HyperOS, Android 16).

## Review Focus
1. **Packet loss bursts (Wi-Fi interference)** → the picture recovers within ~300 ms, with no green or grey smear frames shown. Tests: `prs::fec::recovers_any_k_of_n` (H), `FrameAssemblerTest.dropsIncompleteFrameAndRequestsIdrOnce` (P).
2. **Phone changes network mid-stream (Wi-Fi → 5G)** → the session follows the new address via PROBE without restarting. Tests: `session::follows_new_probe_address` (H), `ReceiverTest.keepsProbingAfterAddressChange` (P).
3. **Rotation or resolution change on the PC (game changes mode)** → capture re-initialises and the stream continues with a keyframe. Test: `capture::reinit_on_mode_change` (H, with a fake duplicator).
4. **Duplicate or reordered input packets** → each event is applied exactly once, in `i` order. Tests: `input::dedup_by_event_id` (H), `InputSenderTest.sendsLastThreeEvents` (P).
5. **Decoder rejects the stream (unsupported profile on a phone)** → fall back to the next codec in the list, then a plain error. Test: `CodecPickerTest.fallsBackInOrder` (P).

## Track H: Host engine (Rust)

### H1: PRS framing, crypto and FEC + vectors
**Files:** `host/src-tauri/src/prs/{mod.rs, header.rs, crypt.rs, fec.rs, frame.rs}`; `docs/prs-vectors.json` (generated by `cargo test prs::write_vectors -- --ignored`).
**Produces:**
- `Header{typ, flags, seq, frame_id, frag, count}` with `encode() -> [u8;16]` / `decode(&[u8]) -> Option<Header>`;
- `Crypt::new(key, session)`, with `seal(dir, &Header, &[u8]) -> Vec<u8>` and `open(dir, &[u8]) -> Option<(Header, Vec<u8>)>`;
- `fec::shards(payload, fec_pct) -> (k, m, Vec<[u8;1152]>)` and `fec::rebuild(k, m, Vec<Option<Vec<u8>>>) -> Option<Vec<u8>>` (`reed-solomon-erasure` galois_8);
- `frame::packetize(frame_id, &FrameHeader, &[u8], fec_pct) -> Vec<(Header, Vec<u8>)>`.

**Tests:** header round-trip; nonce layout; a tampered byte fails `open`; `recovers_any_k_of_n` (random erasures of up to `m` shards); frame size boundaries (0, 1136, 1137, 300 KB); vectors written and read back.

### H2: Capture → NV12 → hardware encode
**Files:** `host/src-tauri/src/engine/{capture.rs, convert.rs, encode.rs}`.
**Produces:**
- `Capture::open(display) -> Capture` with `next(timeout) -> Option<GpuFrame>`, re-initialising on access-lost or mode change;
- `Convert` (D3D11 VideoProcessor BGRA→NV12 plus scaling);
- `Encoder::new(codec, w, h, fps, kbps)` on a Media Foundation hardware MFT (async MFT, D3D11 device manager), with `encode(&GpuFrame, force_idr) -> Vec<Encoded{data, key, capture_us}>`, `set_bitrate(kbps)` and `codecs_available() -> Vec<Codec>`.

**Tests:**
- `reinit_on_mode_change` (fake duplicator trait);
- `encoder_produces_annexb_keyframe_first` (on this PC; ignored when no hardware MFT);
- `set_bitrate_applies_without_restart`.

### H3: Audio
**Files:** `host/src-tauri/src/engine/audio.rs`.
**Produces:** `AudioCapture::start(cb: FnMut(Vec<u8> /*opus*/, u64 /*us*/))`, using WASAPI loopback on the default render device → resample to 48 kHz → 10 ms Opus frames (`opus` crate, static).
**Tests:** a 480-sample frame size; an encoded silent frame is decodable (round-trip with the `opus` decoder); a device change restarts capture.

### H4: Stream session
**Files:** `host/src-tauri/src/engine/{session.rs, bitrate.rs, input.rs, cursor.rs}`; agent handlers `stream.start`/`stream.stop`; `caps += "stream"`.
**Produces:** `StreamSession::start(params, out: Outbox) -> (ready_msg, handle)`, which owns:
- the UDP socket;
- the PROBE handshake (address learning, `follows_new_probe_address`);
- pacing (frames sent spread over ≤ 4 ms);
- IDR on request (≤ 1 per 250 ms);
- REPORT → `Bitrate::on_report() -> Option<kbps>`;
- INPUT → dedup → existing `input::Input`;
- cursor position packets, and `cursor.shape` over the agent;
- a 5 s timeout.

**Tests:** `follows_new_probe_address`; `ignores_unauthenticated_probe`; `dedup_by_event_id`; bitrate AIMD from the protocol rules (loss 3% → ×0.75, stable → ×1.08, floor and step-down after 3 s); `times_out_after_5s`.

### H5: LAN discovery
**Files:** `host/src-tauri/src/mdns.rs`.
**Produces:** advertises `_pcremote._udp.local` on port 47999 with TXT `id=<pc id>`, `v=2`, and `name=<pc name>` (the `mdns-sd` crate). Stops when the app quits.
**Tests:** the TXT contents; re-announce on network change (fake interface list).

### H6: End-to-end loopback test
A test receiver (Rust) connects to the session on `127.0.0.1`, completes PROBE, receives 120 frames, rebuilds them through FEC with 10% of packets dropped at random, and checks keyframe-first ordering and the frame rate. It also logs capture→send latency (target p95 under 12 ms).

## Track P: Phone receiver (Kotlin)

### P1: PRS framing, crypto and FEC
**Files:** `app/src/main/java/com/pcremote/prs/{Header.kt, Crypt.kt, ReedSolomon.kt, Frames.kt}`.
**Produces:** mirrors H1 (a `ReedSolomon` Kotlin port compatible with Backblaze/`reed-solomon-erasure`), using `javax.crypto` AES/GCM/NoPadding.
**Tests:** all `docs/prs-vectors.json` cases (header, seal/open, FEC encode equals the host's parity, rebuild from erasures); a tampered byte is rejected.

### P2: Receiver
**Files:** `prs/{Receiver.kt, FrameAssembler.kt, InputSender.kt}`.
**Produces:** `Receiver(host, port, crypt, scope)` with `frames: Flow<Frame>`, `audio: Flow<AudioPacket>`, `cursor: StateFlow<Cursor>`, `stats: StateFlow<Stats>`, `requestIdr()` and `sendInput(evt)`. It runs the PROBE loop, sends REPORT every 100 ms, and does address-change keepalive.
**Tests:**
- `dropsIncompleteFrameAndRequestsIdrOnce`;
- `rebuildsWithFecUnderLoss`;
- `reportFieldsFromCounters`;
- `keepsProbingAfterAddressChange`;
- `sendsLastThreeEvents` (with increasing `i`).

### P3: Decoder and audio
**Files:** `prs/{VideoDecoder.kt, CodecPicker.kt, AudioPlayer.kt}`.
**Produces:**
- `CodecPicker.supported() -> List<String>`, best first, from MediaCodecList with low-latency capability noted;
- `VideoDecoder(surface)` on MediaCodec async with `KEY_LOW_LATENCY` and the vendor low-latency keys (Qualcomm `vendor.qti-ext-dec-low-latency.enable=1`, MediaTek `vendor.mtk.vdec.lowlatency.mode=1`), releasing every output buffer immediately with render=true;
- `AudioPlayer` (Opus MediaCodec → AudioTrack `PERFORMANCE_MODE_LOW_LATENCY`).

**Tests:** `fallsBackInOrder`; the vendor-key table chooses keys by codec name prefix; `AudioPlayer` buffer sizing is 20–60 ms.

### P4: Stream screen on our engine
**Files:** `com/pcremote/stream2/{StreamActivity.kt, StreamController.kt}`; reuse `StreamOverlay` (connecting, edge panel, keyboard bar, stats pill, coach marks) and `ZoomPan`/`TrackpadModel`.
**Produces:**
- Screen mode starts `StreamActivity` for agent-paired PCs, which sends `stream.start` over the agent, then runs the receiver and decoder;
- input goes over PRS (trackpad/touch through `TrackpadModel`, absolute touch as `mouse.pos`, added to the protocol, keys);
- the phone draws the cursor overlay from CURSOR plus `cursor.shape`;
- stats show the real latency (`captureUs` → displayed, using a PROBE clock-offset estimate).

**Tests:** `StreamControllerTest` with fake agent and receiver (start → ready → receiving; stop on leave; resolution `stream.ready` mid-stream re-configures the decoder).

### P5: Auto-connect
**Files:** `com/pcremote/discovery/Lan.kt`; `HomeController` uses it.
**Produces:** NsdManager browses `_pcremote._udp` and matches the TXT `id` to paired PCs. A matching PC gets its current LAN address added first and connects automatically (Home shows it online with no taps).
**Tests:** TXT parsing; address ordering (mDNS address first, then stored LAN addresses, then public).

## Phase 3: From anywhere

### R1: Rendezvous Worker
**Files:** `cloud/rendezvous/{wrangler.toml, src/index.ts, src/room.ts, test/*.ts}` (Workers + a Durable Object per PC id, with hibernating WebSockets).
**Produces:**
- `GET /v1/host?pc=<id>&proof=<hmac>`: the host's long-lived socket;
- `GET /v1/connect?pc=<id>&device=<id>&proof=<hmac>`: the phone's socket;
- it relays `{"t":"cand",…}` / `{"t":"turn"}` messages between them;
- `POST /v1/turn` returns Cloudflare Realtime TURN credentials (TTL 6 h), using the Worker secret `TURN_KEY_ID`/`TURN_KEY_TOKEN`.

The proof is an HMAC-SHA256 of a timestamp, keyed by a per-device secret the host issues at pairing (stored hashed by the Worker on first registration via the host).

**Tests:** Vitest with Miniflare: auth rejects bad proofs; relays between host and phone; a TURN credential request is proxied (mocked fetch).

### R2: Host and phone remote clients
**Files:** host `src/remote/{rendezvous.rs, stun.rs, punch.rs, turn.rs}`; phone `com/pcremote/remote/{Rendezvous.kt, Stun.kt, Punch.kt, TurnClient.kt}`.
**Produces:**
- the host keeps a rendezvous socket open (one idle WebSocket, a ping every 5 minutes);
- the phone, when no LAN or public route answers, opens rendezvous, and both sides exchange candidates (local, STUN-reflexive, UPnP, TURN relay);
- simultaneous PROBE to all candidates; the first authenticated PROBE wins;
- the TURN client (RFC 8656 Allocate, CreatePermission, ChannelBind, ChannelData) wraps PRS packets when the relay is chosen;
- the control channel (agent) runs over the same path: the existing WSS when it's reachable, otherwise the agent messages tunnel through the rendezvous WebSocket.

**Tests:** STUN binding request/response parse (RFC 5389 vectors); the TURN message builder with the long-term credential HMAC (RFC 5769 vectors); candidate priority ordering; a punch state machine with fake sockets.

### R3: Deploy
Deploy the Worker to the user's Cloudflare account (`wrangler deploy`), create a Realtime TURN key (dashboard or API), and set the secrets. The host gets the Worker URL baked in at build time (`PCR_RENDEZVOUS_URL`).
**Check:** the phone on mobile data (Wi-Fi off) streams from the PC; record the route used (punch or TURN) and the latency.

## Phase 4: Cleanup and release
- **Installer:** remove the Sunshine bundle, Sunshine credentials, `sunshine.rs` bridge, PIN flow, the tray-hiding code and Sunshine firewall rules. Keep ViGEmBus. Uninstalling v1's Sunshine is offered by the installer and never forced.
- **App:**
  - remove `com.limelight.*`, the JNI, `moonlight-common-c`, Game/StreamSettings and the legacy PIN pairing;
  - Screen mode uses only `stream2`;
  - migrate stored PCs (agent pairing already holds everything needed);
  - `IMPLEMENTED_MODES` is unchanged.
- **Release:** sizes measured; real-device run of all modes on the LAN plus remote; version 2.0.0; GitHub release with the APKs and installer.
