# PC Remote v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Executed natively in the session that wrote it (the user asked for build-through-release without stopping), so tasks name files, interfaces and checks rather than repeating every line of code.

**Goal:** Ship 3.0.0: always-reachable host (boot, lock screen, UAC, screen off), phone fingerprint unlock, silent auto-update on both sides, background file transfers with folders and PC browsing, Home Assistant wake, and a dark glass redesign.

**Architecture:** One host exe in three modes (`--service` SYSTEM session 0 → `--server` SYSTEM in the console session → user UI over `\\.\pipe\pc-remote`). The server follows the input desktop for capture and SendInput. The phone gains a foreground TransferService, a biometric-gated PIN vault, a JobScheduler update job and a Home Assistant client.

**Tech Stack:** Rust (tokio, windows 0.62, tauri 2, minisign-verify), TypeScript (vanilla + Vite), Kotlin/Compose (platform BiometricPrompt, JobScheduler, PackageInstaller).

**Spec:** `docs/superpowers/specs/2026-10-17-pc-remote-v3-design.md` (change during planning: no `role:"files"` connection; Android already opens one agent connection per screen, so the TransferService simply owns its own connection).

## Global Constraints
- Version 3.0.0 everywhere (Cargo.toml, tauri.conf.json, package.json, app/build.gradle versionName, versionCode +1).
- No new Android dependencies; one new Rust dependency (`minisign-verify`).
- Android minSdk 26 stays; fingerprint unlock needs API 30+, silent updates API 31+; older versions hide/prompt.
- Data dir `C:\ProgramData\PC Remote` (SYSTEM + Administrators only). Files still land in the console user's `Downloads\PC Remote` unless changed.
- Protocol changes go into `docs/protocol.md` first.
- Release assets keep their names: `PC-Remote-Host-3.0.0-setup.exe` (+ `.sig`), `PC-Remote-3.0.0.apk`.

## Review Focus
1. Upgrade from 2.0.1 on a running PC: paired phones must keep working (store + TLS key migrated, same fingerprint).
2. PC booted, nobody logged in: phone connects, sees the sign-in screen, can type/unlock.
3. Update installer launched by the service must not be killed by its own service stop.
4. A malicious path from the phone (`../`, `C:\`, `\\server`) can never write outside the received-files folder.
5. Phone without biometrics enrolled / API < 30: Unlock offers to type the PIN manually instead of failing silently.

### Task 1: Host process split
**Files:** Create `src/service.rs`, `src/server.rs`, `src/ipc.rs`, `src/win/session.rs`. Modify `lib.rs`, `main.rs`, `commands.rs`, `store.rs`, `log.rs`, `notify.rs`, `win/sys.rs`, `win/dpapi.rs`, `tls.rs`; delete `win/elevate.rs`.
**Interfaces:**
- `win::session::{console_session() -> u32, user_token() -> Option<OwnedHandle>, user_name() -> String, user_profile() -> Option<PathBuf>, spawn_in_session(cmdline, token: Option<&Handle>) -> Option<Child>}`.
- `ipc::serve(handler: Arc<dyn Fn(Req) -> BoxFut<Resp>>, events: broadcast::Receiver<UiEvent>)`; `ipc::Client::call(cmd: &str, args: Value) -> Result<Value, String>`; `ipc::Client::events() -> Receiver<UiEvent>`.
- `data_dir()` = ProgramData path in every mode; `server::migrate(dir)` copies `%APPDATA%` data of the console user, re-protecting the TLS key with machine-scope DPAPI.
**Checks:** unit tests for IPC framing round-trip and migration (temp dirs, fake key); `cargo test`; manual: install, `sc query "PC Remote"`, phone connects.

### Task 2: Secure desktop, display wake, lock state, unlock
**Files:** Create `src/win/desk.rs`, `src/unlock.rs`. Modify `input.rs` (SendInputEmitter follows the input desktop), `engine/session.rs` (capture open follows it), `host.rs` (`unlock`, `lock` push, `locked` in welcome), `proto.rs`.
**Interfaces:** `desk::follow() -> bool` (switch calling thread to the input desktop if changed), `desk::is_locked() -> bool`, `desk::wake_display()`, `unlock::type_secret(&str) -> bool`; `ClientMsg::Unlock{secret}`, `ServerMsg::{UnlockResult{ok}, Lock{locked}}`, `Welcome.locked`.
**Checks:** proto round-trip tests; `unlock::keys_for("12ab")` produces digit VKs + unicode; manual on lock screen and UAC.

### Task 3: Installer
**Files:** `installer/hooks.nsh`, `tauri.conf.json`.
- PREINSTALL: stop + wait the service, kill the server/UI.
- POSTINSTALL: create service (`sc create "PC Remote" binPath= "...\pc-remote-host.exe --service" start= auto obj= LocalSystem`, failure actions restart), ProgramData ACL, firewall, remove old task + HKCU Run, disable Fast Startup (`HiberbootEnabled=0`), enable magic-packet wake on physical adapters, start service.
- PREUNINSTALL: stop/delete service.

### Task 4: Auto-update
**Files:** Create `src/update.rs`; modify `service.rs`, `commands.rs` (check_update via the pipe shows status), `tauri.conf.json` (`createUpdaterArtifacts`), `Cargo.toml` (+minisign-verify). Android: create `update/Updater.kt`, `update/UpdateJob.kt`; manifest permission + job service.
**Interfaces:** `update::check_and_install(pubkey) -> Result<Option<String>>`, `update::pick_assets(release_json) -> Option<(exe_url, sig_url, version)>`; Android `Updater.latest(): Release?`, `Updater.install(file)`.
**Checks:** `pick_assets` test on a sample release JSON; signature verify test with a generated key pair; version compare reuses `commands::is_newer`.

### Task 5: File transfer
**Host files:** `files.rs` (relative paths, `cancel`, `list`, folder offers), `host.rs`, `proto.rs`. **Phone:** create `modes/TransferService.kt`; rewrite `FilesController.kt` into the service, `FilesScreen.kt` (queue, speed, ETA, pause/resume/cancel, folder pick, PC browser), `HomeController`/`ModeSession` forward offers to the service.
**Interfaces:** `files::safe_rel(name) -> Option<PathBuf>`; msgs `file.cancel{id}`, `fs.list{path}`→`fs.list{path,entries}`, `fs.get{path}`; offers carry `name` as a relative path.
**Checks:** traversal tests (`../x`, `a/../../x`, `C:\x`, `\\h\s`, `CON`), folder offer test, Kotlin FileTransfer tests updated.

### Task 6: Wake via Home Assistant
**Files:** `home/WakeOnLan.kt` (add HA call), `settings/SettingsModel.kt` + screen (URL, token), `HomeController.wake`.
**Interfaces:** `HomeAssistant.wake(url, token, mac): Result<Unit>` → `POST {url}/api/services/wake_on_lan/send_magic_packet` `{"mac":…}` with `Authorization: Bearer`.
**Checks:** request-building unit test; manual against the user's HA.

### Task 7: Fingerprint unlock (phone)
**Files:** create `agent/PinVault.kt`, unlock button in `stream2/StreamScreen.kt`, `modes/RemoteScreen.kt` and Home card; settings entry.
**Interfaces:** `PinVault.save(activity, pin)`, `PinVault.reveal(activity): String?` (BiometricPrompt + Keystore AES-GCM key, auth required each use).
**Checks:** unit test for the stored blob format; manual.

### Task 8: Redesign
**Phone:** `ui/theme/*`, `ui/components/Components.kt`, every screen. **PC:** `host/ui/src/theme.css`, views, titlebar.
**Checks:** `./gradlew :app:testNonRootDebugUnitTest`, `npm run build`, screenshots of the PC window.

### Task 9: Release
Bump versions, docs (README, protocol), `cargo test`, Gradle tests, build signed APK + signed installer, commit, tag `v3.0.0`, `gh release create` with exe, sig, apk, notes.
